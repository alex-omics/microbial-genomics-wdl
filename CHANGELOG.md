# Changelog

## [Unreleased]
### Added
- `workflows/rna_seq_counts/rna_seq_counts.wdl` - Paired-end RNA-seq alignment (BWA-MEM) and featureCounts with each sample aligned to its own isolate's assembly, so accessory-genome transcripts and divergent-strain reads a shared reference (PA14) cannot receive are not lost or biased against; also runs against one shared reference (`match_mode = "all_to_one"`). Isolates aligned to their own assemblies carry independent locus tags, so the workflow annotates each assembly with Bakta and builds an ortholog table with Panaroo itself, each skipped if you supply its output (`reference_annotations`, `ortholog_table`) — the same skip-if-supplied pattern as `dna_methylation_calling`. Folded in from the standalone BWA-MEM workflow, which is split into `tasks/bwa.wdl`, `tasks/picard.wdl` and `tasks/featurecounts.wdl`. Validated end to end on synthetic isolates with planted per-gene counts, including with Panaroo and Bakta running inside it; not yet run on Terra
- `tasks/sample_matching.wdl` (`match_samples_to_references`) - Resolves each sample to an assembly by exact name, then by peeling a replicate suffix (letter, number, `rep2`, `replicateA`, ...), and fails the run before any alignment if a sample cannot be matched. Only ever matches names that exist, and never reads a bare digit as a replicate (`PSA_11` is not `PSA_1` plus `1`), because the failure mode is a sample silently aligned to the wrong existing genome. Emits an auditable mapping table; explicit override map and custom regex supported. Tested against the real 81-sample PSA/ARB demux sheet and 16 other replicate spellings. Also validates a supplied ortholog table up front (missing isolate columns, or the `.Rtab` passed by mistake)
- `tasks/featurecounts.wdl` (`merge_count_matrices`) - Combines per-isolate count matrices into a long-format table and, given Panaroo's `gene_presence_absence.csv`, one ortholog-level matrix. A gene an isolate lacks is `NA`, not `0`. Refuses an isolate whose ortholog-table locus tags match none of its counted features (an all-`NA` column with no error otherwise). A counted feature in no ortholog group gets its own `unclustered` row instead of being dropped: Panaroo's `strict`/`moderate` modes discard genes seen in few genomes, which are the accessory transcripts this workflow is for (the workflow defaults to `sensitive`)
- `tasks/annotate_motifs.wdl` (`annotate_motif_membership`) - Adds a `motif` column to `annotate_methylation`'s per-site table: which of an isolate's candidate motifs (de novo + REBASE), if any, each methylated site falls inside. The single per-isolate deliverable combining gene/product/region annotation, promoter windows, and motif context alongside the methylation call, one row per site — new `dna_methylation_calling` output `annotated_tables_with_motifs`
- `workflows/dna_methylation_calling/dna_methylation_calling.wdl` - Per-isolate bacterial methylation calling from ONT modified-basecalled BAMs. Each isolate's reads are mapped to its OWN assembly rather than a shared reference — no single reference captures the accessory genome of an organism this prone to rearrangement, and de novo motif discovery specifically requires it, since motif context is read from whatever the reads were aligned to. Validated end to end on a real 14-isolate *P. aeruginosa* panel on Terra
- `tasks/align_modbam.wdl` - `samtools fastq -T MM,ML,MN | minimap2 -y`, with MM-tag presence checked before and after alignment; losing the tags produces an empty pileup with no error otherwise
- `tasks/modkit.wdl` - `modkit_pileup` (bedMethyl split by 6mA/4mC/5mC) and `modkit_find_motifs` (de novo motif discovery)
- `tasks/bakta.wdl` - Per-isolate annotation with `--keep-contig-headers` hardcoded (not exposed as an input — a renamed contig silently empties every downstream intersect) and `--proteins` support for carrying reference gene names onto independently-annotated isolates
- `tasks/annotate_methylation.wdl` - Joins bedMethyl to the isolate's own Bakta GFF3 (genic/upstream, three floors: coverage, percent-modified, and modified-read count) with `region_length` carried through so site counts can be normalised into a density rather than a proxy for gene length
- `tasks/panaroo.wdl`, `tasks/methylation_orthologs.wdl` - Pangenome-based ortholog join across independently-assembled isolates. Absence is `NA`, not `0`, in the resulting matrix — collapsing the two would manufacture methylation differences that are really gene presence/absence
- `workflows/pangenome/pangenome.wdl` - Bakta + Panaroo, stopping there. No alignment, no tree — coupling pangenome construction to phylogenetics on a large or mixed-quality panel risks paying for a tree search that never converges
- `tasks/rebase_mtase_search.wdl` - MTase homology identification against the REBASE Gold Standard set (BLASTP + motif join, split into two tasks since the BLAST image carries no Python)
- `tasks/motif_landscape.wdl`, `tasks/motif_landscape_summary.wdl` - Three-tier descriptive methylome characterisation: per-isolate motif enrichment vs. genome background, within-genome heterogeneity (uniform vs. bimodal — the phase-variation/regulator-competition signature), and cross-isolate variability by motif and by gene. Deliberately descriptive, not a phenotype association test — the goal is landscape characterisation across a diverse panel, not confirming any one enzyme's activity
- `tasks/utils.wdl` - Shared `name_summary`, `concat_tables`, and `validate_panel` (fails fast on mismatched input arrays or sample names that would break locus tags or pangenome column headers, before the expensive stages run)
- `tests/run_unit_tests.sh` - Fixture-based regression suite for the methylation tasks, run through the real WDL tasks via `miniwdl run` rather than a copy of their logic. Statistics were validated against a synthetic genome with known planted methylation before being fixed as assertions
- `.dockstore.yml` - Registered `dna_methylation_calling` and `pangenome`
- `fetch_reads_from_sra` - Fetches a single SRA/ENA/DDBJ run accession and emits gzip-compressed FASTQ, independently callable in Terra. Folded in from a working script (originally named `fetch_sra_to_fastq`, renamed before merge for clarity) already validated against a live 300+-row Terra data table (row-per-accession scatter via `this.SRA_ID`, kept unchanged rather than converted to an `Array[String]` batch input - see `workflows/fetch_reads_from_sra/README.md` for why). Detects paired/single/orphan-read layout from what `--split-3` actually produced instead of assuming paired-end, and reports platform/instrument as their own outputs (best-effort, via ENA's `filereport` API) - kept separate from `layout` rather than pre-combined into one string, so a Terra table can be filtered/sorted on either independently. `read1`/`read2`/`sra_tools_version` output names preserved unchanged so the live Terra method config's column mappings keep working. Docker pin fixed from `staphb/sratoolkit:latest` to `:3.3.0` while porting, matching every other task in the repo
- `pyseer_gwas` - Standalone pyseer LMM/LRT association workflow, independently callable in Terra. Accepts any block x isolate presence/absence Rtab (Panaroo gene families or pangenome-network modules), with optional `--lineage` effects, a `covariate_combinations` scan (deliberate single- or multi-column groups, not an automatic powerset search), and a gene/module-annotation join that never modifies pyseer's own output. README documents, with measurements against the real image, that RST/OspC/MLST/BAPS are categorical (never quantitative) and that jointly loading several of them is a real degrees-of-freedom risk, not just a style choice
- `aarvani1/pyseer:1.4.2` - Lean standalone pyseer image, deliberately separate from `microgwas-pyseer` (which backs `multimodal_gwas` and carries that pipeline's dependencies). Built and pushed to Docker Hub, digest-pinned in `tasks/pyseer.wdl` and `workflows/pyseer_gwas/pyseer_gwas.wdl` (see `docker/pyseer/CHANGELOG.md`)
- `multimodal_gwas` - Terra WDL translation of microGWAS (Burgaya et al. 2025), targeting faithful reproduction of the published *E. coli* virulence GWAS as Milestone 1
- `workflows/assembly_qc/assembly_qc.wdl` - Scatters QUAST, BUSCO, and CheckM2 over a set of assemblies and emits one merged summary TSV
- `tasks/checkm2.wdl` - CheckM2 completeness and contamination, with the DIAMOND database supplied as a `File` input (Terra-native) or downloaded at runtime
- `busco-prokaryota:5.8.0` - Docker image with the complete OrthoDB v10 prokaryote set (99 datasets) plus placement files for offline auto-lineage
- `tasks/busco.wdl` - Reusable BUSCO task with auto-lineage and explicit lineage support, plus an optional lineage tarball override

### Changed
- `tasks/panaroo.wdl` - New optional `sample_names` input, naming each isolate's column in `gene_presence_absence.csv` independently of its GFF filename. Panaroo otherwise labels columns after the filename, so a GFF supplied under any other name produced a column no downstream step could find. Omitted, behaviour is unchanged
- `workflows/pyseer_gwas/pyseer_gwas.wdl` - Dropped the separate `annotate_significant` call; `gene_significant` is a row subset of `gene_results` with identical columns, so annotating it separately was redundant - filter `gene_results_annotated` instead. Added an equivalent annotation join for the `covariate_combinations` scan's long-format table (`covariate_scan_combined` -> `covariate_scan_combined_annotated`/`_readable`), which had never been joined against the Panaroo annotation table before
- `tasks/modkit.wdl` - `modkit_find_motifs` moved off `preemptible` (1 → 0) and its default `cpu` raised 8 → 32. The task can run over an hour on a deeply-covered genome with no checkpointing, so a mid-run preemption forced a full restart; modkit's own docs describe the search as heavily parallel and use `--threads 32` in their own example. Both observed directly: pre-fix runs saw repeated multi-hour preemption/restart cycles on the real 14-isolate panel, and post-fix runs completed every shard on the first attempt
- `tasks/motif_landscape_summary.wdl` - Gene-level ranking now breaks CV ties on mean density instead of leaving them in dict-iteration order. CV is scale-invariant, so on the real panel 252 unrelated genes tied at an identical CV purely because they shared the same "signal in exactly 1 of 14 isolates" shape, regardless of how large that signal actually was — the ranking wasn't wrong, just not doing real triage inside those ties

### Fixed
- `rna_seq_counts` (from the standalone BWA-MEM workflow) - Pinned images that cannot run: `staphb/bwa` ships no samtools (the alignment task pipes into it), and `staphb/picard` and `biocontainers/subread` do not exist on Docker Hub. `featureCounts -p` without `--countReadPairs` counts each mate separately (subread >= 2.0.2), doubling every fragment. `ignore_duplicates` now defaults to false: without UMIs it discards independent RNA-seq molecules in proportion to expression. All found by running the real images
- `tasks/annotate_methylation.wdl` - Was filtering on coverage only, so every evaluated base reached the output table; the ortholog matrix built on top of it was effectively reporting gene length rather than methylation. Now filters on coverage, percent-modified, and modified-read count together
- `tasks/annotate_methylation.wdl` - `bedtools intersect -wa -wb` column offset was wrong by one field, writing the feature's end coordinate into the `feature_strand` column and the strand into `product`; caught by hand-verifying the real column layout against bedtools 2.31.1, not by inspection
- `tasks/motif_landscape_summary.wdl` - Sorted motif rows by a formatted string (`"%.3f" % cv`) instead of the underlying float; crashed on first real invocation, caught only by actually running the task
- `tasks/rebase_mtase_search.wdl` - `evalue` was a `Float` default of `1e-25`; WDL's string interpolation renders a float that small as the fixed-decimal text `"0.000000"`, which BLASTP then rejects as a non-positive cutoff. Changed to a `String` — this would have failed identically on Terra, not just in local testing
- `tasks/rebase_mtase_search.wdl` - REBASE entries recognising more than one degenerate sequence for the same enzyme (e.g. `M.BceSV`: `"GGCC,GCNGC,CCGG,GGNCC"`) pack them into one comma-joined `Motif` field; passing that through unsplit produced a non-IUPAC "motif" that crashed `motif_landscape`'s regex translation on the literal comma. Only caught by running the real 14-isolate panel — every isolate carrying one of these multi-motif enzymes was affected, not just the first one to reach that stage. Now split per motif at the point the REBASE table is read
- `tasks/modkit.wdl` - `modkit_find_motifs`'s `motifs` summary field collapsed column 1 (`mod_code`, e.g. always `"a"`) instead of column 2 (the actual motif sequence), so `summary_tsv`'s `motifs` column silently read `"a,a,a,a"` for every isolate instead of the discovered sequences
- `tasks/motif_landscape.wdl` - `in_any_window()` linearly scanned every genomic occurrence of a motif for every bedMethyl site being tested; for a motif occurring thousands of times against millions of sites, this made `motif_landscape` take up to two hours on some isolates. Replaced with a binary search over the (already-sorted) occurrence list — O(log n) instead of O(n) per site, same output on the regression suite
- `tasks/pyseer.wdl` - `pyseer_association`'s `covariate_combinations` scan failed on real BBSS data with `ERROR: covariate column 'BAPS' ... not found in covariates_file header`, but only for `BAPS`, the *last* column - `RST`/`OspC`/`MLST` matched fine. Cause: `covariates_file` has Windows CRLF line endings, and `head -1`/`awk` only recognise `\n` as a line terminator, so the true last header field was `BAPS\r`, which never string-equalled `col="BAPS"`. pyseer's own Python-side read of the same file was unaffected (text-mode file reads normalise `\r\n` to `\n` automatically) - this only broke our own bash header lookup. Fixed by stripping `\r` when reading the header (`tr -d '\r'`), confirmed by the OOM-fix rerun: the split from `pyseer_lineage_effects` let the workflow get past the previous OOM and reach this scan for the first time at real scale
- `tasks/pyseer.wdl` - `pyseer_association` with `run_lineage_effects` set OOM'd against real 200-isolate BBSS data (6,427 variants, 2.5 MB Rtab) in under a minute on a 32 GB machine - too fast and too small to be a genuine memory shortage. Cause: `--lineage` was bolted onto the same call already running the full `--lmm` test across every variant. Split lineage effects into their own task, `pyseer_lineage_effects`, run against only a small slice of `presence_absence_rtab` (enough for pyseer to initialise, not the full matrix) - matching the pattern already validated in the `multimodal_gwas` translation's `run_pyseer` task, which runs its lineage pass against a 10-line slice of the variant file for the same reason. Never reproduced on the 8-sample smoke fixture (too small to trigger it), only caught against real-scale Terra data
- `tasks/pyseer.wdl` - `pyseer_association` with `run_lineage_effects` set failed inside the container ("Must also provide a distance matrix to report lineage effects"): pyseer's `--lineage` requires `--distances` unconditionally, even when `lineage_clusters` is supplied - it is not just the fallback for MDS-derived lineages. `pyseer_similarity_from_phylogeny` now also emits a plain (non-`--lmm`) distance matrix from the same tree, wired through automatically at the workflow level. Caught by the new end-to-end smoke test in `tests/run_unit_tests.sh`, which a single-task fixture test could not have caught
- `tasks/busco.wdl` - Pointed `--download_path` at the consolidated `/busco_downloads`; the previous path held no manifest, so auto-lineage could not run and only spirochaete datasets resolved
- `tasks/busco.wdl` - `grep` for the lineage-used line had the filename inside the pattern with no file argument, so it read stdin and returned nothing
- `tasks/busco.wdl` - Summary was copied from `<sample>_busco/` while BUSCO wrote to `<sample>/`; auto-lineage also emits several `short_summary*` files, which broke the glob
- `tasks/busco.wdl` - Runtime used `disk:` / `local_disk`; Terra requires `disks:` / `local-disk`, so the attribute was silently ignored
- `tasks/quast.wdl` - Invoked `quast`, which does not exist in `staphb/quast:5.2.0` (the entrypoint is `quast.py`)
- `tasks/quast.wdl` - Quoted domain flag expanded to an empty positional argument for prokaryotes, which QUAST read as an empty input filename
